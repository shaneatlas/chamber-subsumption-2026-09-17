## 7. PostgreSQL: use the current index correctly before designing another one

### 7.1 Three physical designs, not interchangeable names

U4 distinguishes the existing stored-vector HNSW, a transform expression index with unchanged heap, and a generated stored column with its own ordinary index. Preserve that distinction and the reported negative search for transform indexes at its inspected scope. A schema export search is not a universal live-catalog proof.

PostgreSQL stores expression-index results in the index; indexed lookup does not recompute the transform for every heap row. Generated columns are optional. Exact SQL spelling is not the rule: resolved functions/types/operators, expression structure and the applicable predicate determine compatibility. Whitespace and equivalent schema qualification are not different coordinates. [W02; W05]

The operator's raw ascending `<=>` ordering is the correct form to qualify against the current cosine index. Displaying `1-distance` in SELECT does not rewrite ORDER BY. An eligible shape is not a guarantee that the cost-based planner chooses HNSW; on a small permitted cohort, an exact scan can be correct and preferable. [U4; W01]

No binary/halfvec/subvector index, generated column, new stored vector, index rebuild or DDL is part of the 23-ID repair.

### 7.2 Two additional PostgreSQL qualifications

A partial model index is a design option, not an instruction to create one now or a guaranteed win. Its predicate has to be implied by the actual query; generic prepared plans can fail that implication for parameters. Qualify actual execution/plan behavior rather than defeating parameterization with untrusted interpolation. [W04]

The claim that a GUC-dependent wrapper will necessarily be rejected is too strong. PostgreSQL requires appropriate immutability declarations for index expressions, but explicitly warns that false IMMUTABLE declarations are possible and unsafe. Correct volatility is a contract to inspect, not automatic proof of semantic purity. [W05; W06]

`vector(1536)::vector(1024)` is not model migration or truncation. A compatible-dimensional type annotation does not translate coordinates. A Matryoshka prefix can be an optional reduced-space experiment for a model trained to support it; bind both query and document transform and normalization. The provider describes supported reduced dimensions for voyage-3-large, but no Source experiment was performed. A 256-d Voyage prefix is not FastRP 256. [U4; W13]

### 7.3 Filtered underfetch: counts, ordering and recall differ

U4 reports 704 eligible sf2 rows within 4,144,664, with one result under a fixed scan and five under relaxed iterative scanning. Retain it as a measured result reported by the operator. The expected-survivor arithmetic is a heuristic, not a model of correlated HNSW candidates or proof of actual beam size.

The upstream contract supports iterative scanning, ordering modes and resource controls. Relaxed results can need an explicit outer sort; that sorts only the candidates obtained. `max_scan_tuples` is approximate and does not bound the initial scan, so it is not a hard universal work limit. [W01]

**A cardinality guard cannot certify exact neighbors.** If the exact set is {a,b,c,d,e} and five returned IDs are {a,f,g,h,i}, count sufficiency passes while exact-neighbor recall is 1/5. This is a mathematical counterexample, not a Source test result.

A thresholded query can correctly return fewer than k. Do not count the unrestricted table and then fault a restricted query for honoring its policy.

`UnderFetchError` can correctly identify an incomplete query opportunity. Do not silence it by lowering the expected population, treating missing measurements as an empty corpus, or deleting candidate obligations. Do not call five-of-five an ANN-recall pass.

## 9. GNN, spectral and KGE work: optional research, not a prerequisite

### 9.1 Correct the trained-model classification

The report supports an inspected distinction between existing untrained graph representations and unwired trained-model candidates. Do not conclude both “Source does not run a GNN” and “FastRP is the production GNN” as equivalent implementation claims. Use **untrained structural embedding/message-passing method** for the reported FastRP path. Source-wide absence remains bounded by the scope of the repository/installation inspection. [U3]

GraphSAGE learns an inductive aggregation function and requires a compatible trained model plus projected features at inference. An isolate can retain a transformation of its own features; that is not raw Voyage identity or proof of useful retrieval. Current GDS examples also have implementation-specific procedure names and graph-orientation requirements. [W09; W11]

HashGNN is not necessarily blocked by a missing Voyage property: GDS supports generated features as an alternative to input feature properties. That alternative would not fulfill the desired text-informed fusion. If Voyage is required by the proposed experiment, explicitly supply the qualified features or keep the experiment ineligible. [W08]

### 9.2 Features must reach the computation, not necessarily the persistent graph

An authorized temporary graph can, on a supporting execution path, be constructed from client-supplied node features and relationships. The GDS Python client documents DataFrame graph construction. A keyed, versioned PG feature set can therefore be a candidate input without writing the same vectors permanently to Aura first. [W10]

This is a possible implementation route to evaluate later, not a bypass of current Search/AGA restrictions. Source must already support or separately admit the feature-transfer owner, data scope, compatible model, complete ID mapping, capacity and output sink. A missing permanent property is not a universal technical block; absent qualified projected features is the actual feature block.

Nor does public `graph_gds: VOID` prove no internal GNN procedure exists. Presence, license/support, model training, authorized execution and useful output are distinct observations.

### 9.3 Do not infer method authority from an execution mode

A `mutate` procedure changes a projection; a `write` procedure persists graph properties. Neither automatically belongs to plane B just because its method name includes write. Plane B's authorized Skill suite does not grant CorpusEntity GraphSAGE writes. Similarly, a stream result subsequently persisted by Python has an external write effect even though the algorithm mode was stream.

Keep current R2 owner boundaries. Do not move a training or broad-projection workload into an authorized route by vocabulary alone. No SAGE/HashGNN experiment, weight training, KGE, vector field, or ANN is required for the pairs-only repair.

### 9.4 Graph provenance must survive feature fusion

Type/domain edges can be legitimate typed relations, but they do not imply semantic corroboration. Their exclusion from a particular semantics-focused experiment is an evaluation decision, not automatic deletion from Source. A same-parent cluster is highly dependent evidence.

An edge predicted from embeddings and then used to train another embedding is feedback. A `source=gnn` tag records origin but does not itself control leakage. Preserve graph snapshots, generator versions, train/evaluation separation and admission policy. Compare semantics-only, topology-only and qualified fusion using the same allowed evidence. Similar-text/different-topology and different-text/similar-topology are disagreement signals, not automatic noise/signal or truth classifications.

If legitimate inferred edges are later admitted, their presence need not be forbidden forever; use explicit generations and independent acceptance so a model does not validate itself through its own newly minted edges.

### 9.5 Spectral and RotatE qualifications

A Laplacian eigenspace probe is not automatically a linear GCN or a trained neural model. Sign canonicalization does not resolve arbitrary rotations inside a repeated-eigenvalue eigenspace. For a disconnected graph, multiple zero eigenvalues can exist, so dropping only one zero eigenvector may not remove every component-constant direction. When a dimension cut splits a degenerate space, some distance/volume results can depend on the basis choice. These are mathematical implications to test with bound ordering, tolerances and invariant measures; no Source spectral test was run. NumPy supplies an eigensolver, not a guarantee that an application has solved those identifiability questions. [U3; W12]

RotatE is a relation-aware knowledge-graph embedding method, not a requirement for a particular GPU/library or a GNN. Its learned distances do not mint factual authority. The proposed 400-dimensional layer, DGL-KE path and design-score uplift remain unimplemented hypotheses on U3's evidence. Relation provenance and factual support matter more than whether an edge is named SHARES_FACT. [U3; W16]

Node2Vec's lack of a built-in inductive mapping does not logically force every possible implementation to redo all walks after one insertion. Nor does GDS procedure absence follow from a documentation summary. Keep those as conditional integration/scaling questions, not reasons to delay the current path.
