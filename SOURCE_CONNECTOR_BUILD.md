## 2. What the sources jointly preserve

The Source utility is intended to reduce repeated reconstruction, preserve useful context and distinctions across clients, select the operation that fits the task, carry work through interruption, and retain changes that improve later work. The connector/harness comparison preserves an appropriate place for inexpensive cognition and specialized services without assigning them Source's acceptance authority. [S28:L72–L104](source_views/S28.html#L72)

The high-level decomposition remains:

```text
Admitted user/client objective
  → thin connector / CLI / optional presentation
  → current Source authority + full objective + relevant state
  → unified-router: capability / depth / evidence / executor
  → existing permitted dispatcher and custody owner
  → native query, specialized computation, bounded harness or durable operation
  → complete result and applicable target observation
  → actual reader and scope-specific acceptance

Separate, selected learning tempo:
  qualified episode → candidate → independent evaluation → scoped admission
  → real unseen later consumer → attributable result → drift/retirement response
```

This is the preserved **logical division**, not a request for new services at each arrow. Source should use deterministic existing operations when adequate and selected model work where it adds value; no provider or mandatory multi-agent fanout is established by the comparisons. [S32:L24–L58](source_views/S32.html#L24) [S23:L582–L592](source_views/S23.html#L582)

The longitudinal sources separate composition from proof. A durable query, procedure, or evidence packet can preserve value beyond one generated answer. But executable form alone does not certify data quality, source completeness, permission, or future usefulness. The current execution packet keeps both the positive work obligation and its applicable verification.
